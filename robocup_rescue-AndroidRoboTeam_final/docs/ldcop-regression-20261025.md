## 关键差异与修复

### 1. 分层规划提前返回，绕过本地救援和保底选人

原来的 `SEUHumanDetector.calc()` 优先考虑当前建筑内可装载的平民；
`SEUFBHumanDetector.calc()` 优先考虑同地点仍被埋压的平民，再进行远程选择。
v2 在这些逻辑前加入“分层开启 -> select -> 无条件返回”。
这意味着远程规划可以抢走原本即刻可执行的本地救援，且 select 返回 null 时，
不会进入原有 getTargetByDistance / getTargetByTimeAndBuriedness 回退。

修复：恢复原本本地优先的顺序，其后仍优先使用 L-DCOP 选人；仅当其无可执行目标时，
才调用原有选择器。不关闭 L-DCOP、不加其他算法，也不把保底逻辑伪装成 L-DCOP 成功。
保底实际选到目标时记录 `[LDCOP-FALLBACK]`，注明角色、时刻和目标。

### 2. 零伤害被错误视作“缺失伤害”

`observe()` 原先仅接受 damage > 0，否则统一替换成默认伤害 20。
一个明确观测到 damage=0 的存活人员也会被推算出有限死亡时间，再被时间窗排除。

修复：区分“未定义”和“已定义为 0”。仅未定义时使用默认伤害；
零伤害下不凭空生成死亡期限。死亡人员仍不得进入可救任务。
这是当前观测下的估计，不代表未来受伤后永远不会死亡；后续伤害更新会重算。

### 3. 重规划能挤掉已经认领的任务

原先 owners 只限制“谁能接”，没有保证认领目标先占该 Agent 的队列容量；
新任务可能先塞满队列，或者插到已认领队首之前。
这与运行时每 5 步重规划结合，可能使已经移动的 Agent 转向其他目标。

修复：可行的有效认领任务先入队，再分配新任务，并保护已认领的队首不被普通插入抢占。
仍检查全部时间窗，失效或不可行的认领不会阻止分配其他可行任务。

### 4. 显式非工作状态没有撤销旧认领

原实现仅增加/续租，收到非 MOVE/RESCUE/LOAD 的状态也只等 TTL 到期。
修复：收到该角色明确的非相关动作时立即移除旧认领；
普通指向建筑/道路的 MOVE 仍不会误取消指向人的意图。

补充 `[LDCOP-REJECT]` 日志，区分第一段路径不可达、实际路径超出时间窗，
便于解释“计划非空但未执行”的情况。

Joao 分别仅 116、89 次是 candidates=0。
因此大量空队列发生在“有候选人”的情况下，与严格时间窗、两层强耦合、所有权/局部信息限制相符。
**空队列率是规划调用统计，不等同于实际闲置步数或死亡人数**，尤其空计划会触发频繁重规划。

## 保留的限制

当前正常比赛版仍是基于局部观测的分层插入式排程，不是 paper 包的同步 BMS 实验实现。
尚未引入多人联合挖掘模型；一名规划救援者的时间估计、只保留 12 个候选、
必须能安排实际运输才保留救援等约束仍可能造成保守拒绝。
本次通过保底接续避免这种拒绝直接切断原有行为，但没有宣称所有模型问题均已解决。
没有调整任务上限、速度、伤害默认值或靠无限等待改变比赛条件。
