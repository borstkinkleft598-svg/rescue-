# L-DCOP v4：执行进展、运输接力与有限助援

## 目标与边界

依据original、较早修复版、v3三轮回放继续修正当前实现，目标是提高跨图稳定性。
v3的Paris/Sakae有净收益，但其余多图倒退；因此不是在已证实全面有效的版本上盲目加参数。
只修改非original项目，不增加新的DCOP求解器，不修改服务器场景、随机种子、人数和完整步数。
不按地图名切换Agent策略；测试顺序按退化案例优先排列。NY仍不运行。
新版本是候选修订，不能保证所有图上升，也不宣称完整论文数值复现。

## 针对回放问题的改动

### 1. 认领必须有进展，不能靠心跳无限占位

- DispatchProgress区分“最后收到消息”和“最后取得进展”：距离缩短或同地点实际工作才更新进展时间。
- 连续12步没有缩短到目标的距离，认领不再阻止其他队员选择该目标。
- 本机远程目标停滞后释放队列，并对同一目标冷却5步；正在同地点施救/装载的机会不被此机制赶走。
- 认领人数满时，明显更近的消防仍可进入距离/ID排序（新加入者加2步迟滞惩罚），不再仅因别人先认领而永远被排除。
- 工作状态广播参考上一时刻真实ActionRescue，不再仅凭“站在目标地点且想救”就宣称已工作；工作状态变化会立即刷新消息。
- 消防/救护消息先用ADF通用MessageUtil合并，保留直接视野优先；实际通信位置参与距离和同地点判断。
- 普通区域MOVE更新进度并清除旧working状态，但不续签旧的人物目标租约。

限制：这里只使用普通队伍消息，没有可靠确认协议；丢包、延迟、距离绕行都可能使判断偏差。
“超过12步无进展”是可配置保护阈值，不是从单轮成绩证明的最优参数。

### 2. 已脱困伤员优先接车

- 运输层先检查活着、未被埋压、位于非Refuge区域且需要运输的平民，覆盖道路和建筑。
- 远程优先级仅用于受伤平民，不把远处可自行撤离的健康平民置于伤员之前；原有就地破损建筑内装载机会保留。
- 就地可装载的直接观察伤员优先，不再依赖“必须身处破损建筑”的旧入口。
- 远程候选先取近处6个及当前承运目标，用真实首段路径、运输时间和存活窗口校验。
- 紧迫但仍可完成的任务优先，否则优先较早完成；4步以内的小差异不轻易切换当前可行承运目标。
- 已载人救护车不再规划第二个乘客，其原有送往Refuge动作不改变。
- 已载人的队友不再被当作能为另一个伤员提供可靠接车服务。
- 没有可行现成乘客时仍保留原有L-DCOP分层插入排程与保底选择，不取消救援→运输依赖。

这针对SF“更早脱困却一直没人装载”和Joao的运输延迟。路线受阻、医护休息等仍可能影响执行。

### 3. 允许有边界地从远程目标转去附近助援

- 保留原有最大3人、助援路程≤8步、收益检查和确定性名额排序。
- 不再把所有持有远程fallback意图的队员永远视为不能帮助别人。
- 只有附近实际作业目标、预计至少节省4步、当前任务有足够余量且当前路程明显更远时，才允许助援改派。
- 已经实际开挖的本机队员不被随便拉走；不是取消协作上限，也不是让所有消防聚集。

这针对Berlin重埋压单人挖不完，以及此前助援分支不触发。实际作用须看完整回放，不能仅由单元测试判断。

### 4. 关闭项目未使用的整局世界历史

- SEUSearch和SEUFBSearch原来在resume/preparate无条件requestRollback。
- 本地ADF实现将实体按时间、属性保存在rollback Map；项目源码没有调用带时间参数的历史世界查询。
- 改为World.keepRollbackHistory=false默认；当前WorldInfo仍正常更新，服务器日志和完整回放仍照常保存。
- 调试需要时可单独打开此配置，不改其他策略。对载客状态做逐步集合缓存，并缓存当步最近Refuge查询，避免重复扫描。

这是有代码依据的内存开销削减，VC是否能在同样6GB堆上完整跑完仍待验证；不能称已定位全部OOM根因。
